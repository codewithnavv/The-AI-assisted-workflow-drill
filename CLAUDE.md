# Project rules

- Read `WORKFLOW.md` and the relevant source files before making changes.
- Keep each requested change scoped to its exercise branch; do not silently
  transfer work between branches.
- Preserve existing user changes. Ask before resolving conflicts that could
  discard or alter that work.
- Prefer small, complete changes that follow the project's existing structure
  and conventions.
- Update directly related documentation and tests when behavior changes.
- Run relevant checks and state their actual results. Do not claim unrun checks
  passed.
- Do not commit credentials, secrets, or unrelated files.
- Do not create a commit or push unless requested.
